# 工程接手指南

> Submachine_demo 省级_ai 分支 · 水下机器人下位机
> 基于 SGA 库 V2.8 (2023-10-15) · STM32F103VC · HAL 1.1.7
>
> 配套阅读：[SGA库代码规范V1.1.md](SGA库代码规范V1.1.md) · [句柄资源示例.txt](句柄资源示例.txt) · [工程维护记录.txt](工程维护记录.txt)

---

## 0. 一句话理解这个工程

> **CubeMX 不在场。** 所有外设的引脚、时钟、DMA、中断都以 C99 designated-initializer 写在
> [config.c](../Apply/Logic/Src/config.c) 的「句柄结构体实例」里，
> [task_userinit.c](../Apply/Task/Src/task_userinit.c) 调一次 `Drv_xxx_Init(&handle)` 就完成全部初始化。

如果你以前用 CubeMX 改引脚，在这里改的方法是：**直接编辑 `config.c` 里那个句柄的 `.tGPIO[x].tGPIOInit.Pin` 字段。**

## 1. 目录结构

按"层级越低越不可改"原则组织（来自 [工程目录介绍.txt](工程目录介绍.txt)）：

```
Submachine_demo/
├── Doc/                工程文档（本文件所在处）
├── Apply/              应用层 ★ 经常改
│   ├── Logic/          业务逻辑（main / usercode / config / threadpool）
│   └── Task/           业务任务（系统初始化 / 用户初始化 / IRQ / 推进器动作）
├── Bsp/                板级层
│   ├── Algo/           算法库（PID、CRC、Hex/Dec 转换）
│   ├── Dev/            设备驱动（PS2 手柄）
│   ├── OCD/            片外外设（JY901/ADS1256/AT24CXX/DS3231/OLED/MS5837/RM3100/FatFs/SDCard）
│   ├── FatFs/          FatFs 源
│   └── RTOS/           FreeRTOS + RT-Thread 内核
├── Driver/             驱动层（SGA HAL 封装）★ 架构开发者才能改
├── Hardware/           STM32F1/L4 HAL + CMSIS（不要动）
└── Project/            Keil/EIDE 工程文件
```

| 层 | 命名前缀 | 用途 |
|---|---|---|
| Driver | `Drv_*` | 片内外设封装（GPIO/UART/SPI/I2C/PWM/...） |
| Bsp/OCD | `OCD_*` | 片外外设驱动（传感器/存储/显示） |
| Bsp/Dev | `Dev_*` | 复合设备（PS2 手柄等） |
| Bsp/Algo | `Algo_*` / `PID_*` | 算法（CRC、PID 等） |
| 本地静态 | `S_*` | 当前文件内部使用的子函数 |

## 2. 与普通 CubeMX 工程的差异

| 维度 | CubeMX 工程 | 本 SGA 工程 |
|---|---|---|
| 外设配置 | 散落的 `MX_xxx_Init()` | 集中的「句柄实例」`tagUART_T Uart1 = { ... }` 在 [config.c](../Apply/Logic/Src/config.c) |
| 初始化调用 | 每个外设一行 `MX_*_Init()` | 统一 `Drv_xxx_Init(&handle)` |
| 改引脚 | 回 CubeMX 重新生成 | 直接改 `config.c` 中对应 `.tGPIO[x]` 字段 |
| 模块开关 | `stm32f1xx_hal_conf.h` 里的 `HAL_xxx_MODULE_ENABLED` | [drv_hal_conf.h](../Driver/Inc/drv_hal_conf.h) 里的 `DRV_HAL_xxx_ENABLE` |
| 命名规范 | 任意 | **强制 SGA 规范**（uc/us/ul/f/b/t 前缀，详见规范 V1.1） |
| 中断 | CubeMX 生成空函数 | [task_irq.c](../Apply/Task/Src/task_irq.c) 里只调 `Drv_xxx_IRQHandler(&handle)` |
| RTOS 切换 | 改工程麻烦 | [drv_hal_conf.h](../Driver/Inc/drv_hal_conf.h) 里取消 `RTT_ENABLE` 或 `FREERTOS_ENABLE` 注释 |
| 注释/文档编码 | UTF-8 | **GBK**（VSCode 要切编码） |

## 3. 启动流程

[main.c](../Apply/Logic/Src/main.c) 裸机三段式：

```c
int main()
{
    Task_Sys_Init();      // 1) SGA 库底层启动 (Drv_HAL_Init)
    Task_UserInit();      // 2) 用户外设初始化 (PWM/UART/JY901/PID/IWDG)
    UserLogic_Code();     // 3) 用户主循环 (while(1))
}
```

RTOS 模式下 `UserLogic_Code()` 内创建线程，再调 `osKernelStart()`。

### 4.3 [usercode.c](../Apply/Logic/Src/usercode.c) ★ 业务逻辑
`UserLogic_Code()` 主循环：

1. 串口 1 DMA 收树莓派字符串指令
2. `thruster_start_open()` 字符串匹配派发动作（`JSB n Press/Release`）
3. `jy901_yaw_anti_forward_open()` —— 位置式 PID + 积分分离 + 速率限幅 + ESC 死区补偿；按 `forward_count` 在初始方向 / +180° 之间往返
4. `jy901_yaw_anti_rotate_open()` —— 三段式速度规划（远段 PID / 中段固定减速 / 近端蠕行）的 180° 转向
5. `Drv_IWDG_Feed(&demoIWDG)`

文件内对外函数（声明在 [usercode.h](../Apply/Logic/Inc/usercode.h)）：

```c
void UserLogic_Code(void);                // 主入口，含 while(1)：收指令 → 派发 → PID → 喂狗
void thruster_start_open(void);           // 解析 RaspberryPi_data 字符串，按指令派发到 thruster_* 或置标志位
void jy901_yaw_anti_forward_open(void);   // 直行偏航稳定（位置式 PID）；首帧锁基准角 oneoneone，后续按往返次数算目标角
void jy901_yaw_anti_rotate_open(void);    // 180° 自转（三段式：远段 PID 主导 / 中段固定减速 / 近端蠕行 + 方向锁存防边界抖动）
void jy901_yaw_anti_rotation_cancel(void);// 关闭直行/旋转标志，PID_Clear，左右推进器复位 1500
void forward_adjust(int left_offset, int right_offset);   // 直行模式输出：左右推进器 1700 ± offset，1400-2000 限幅
void rotate_180_adjust(int left_offset, int right_offset);// 旋转模式输出：左右推进器 1500 ± offset，含 40us 死区补偿，1300-1700 限幅

/* static 内部 */
static float NormalizeAngle(float angle);                  // 把任意角归一化到 [-180, 180]
static float AngleDifference(float target, float current); // 最短路径角度差，规避 ±180° 跳变
```

关键全局变量：

| 变量 | 作用 |
|---|---|
| `RaspberryPi_data[150]` | DMA 接收缓冲，每次循环 memset 清零 |
| `forward_count` | 已收到的"直走"指令次数；奇数=正向，偶数=反向，用于往返 |
| `oneoneone` | 第一次直走时锁定的永久基准角，后续目标角都基于它算 |
| `forward_yaw_target` / `turn_180_target` | 直行/旋转的当前目标偏航角 |
| `forward_open_flag` / `rotate_180_open_flag` | 直行/旋转使能位 |
| `forward_yaw_get_flag` / `right_rotate_180_get_flag` | 防止重复初始化目标角的"取过一次"标志 |
| `left_offset` / `right_offset` / `yaw_output` | PID 输出缓存，便于调试观察 |
| `rotate_180_ready_count` | 自转到位后的稳定计数，连续 3 帧到位才退出 |

支持的指令：

| 树莓派字符串 | 触发动作 |
|---|---|
| `JSB 3 Press` | 垂直上升 (thruster[2/3] = 1750) |
| `JSB 3 Release` | 垂直停止 (1500) |
| `JSB 0 Press` | 垂直下潜 (1250) |
| `JSB 7 Press` | 直行（带 PID 偏航稳定，往返计数+1） |
| `JSB 7 Release` | 停止直行 |
| `JSB 5 Press` | 右转 180° |
| `JSB 6 Press` | 左转（无 PID） |
| `JSB 11 Press` | 全推进器 1750（测试） |

## 7. 接手开发清单（菜谱）

### 7.1 改一个引脚
1. 在 [config.c](../Apply/Logic/Src/config.c) 找到对应句柄。
2. 改 `.tGPIO[x].tGPIOInit.Pin` 和 `.tGPIOPort`。
3. 不需要重新生成任何工程文件，重新编译即可。

### 7.2 加一个新片外传感器（OCD 层已有的）
1. 翻 [句柄资源示例.txt](句柄资源示例.txt) 找到对应外设的句柄模板。
2. 复制到 [config.c](../Apply/Logic/Src/config.c)，改名（如 `tOLEDMain`）、改引脚。
3. 在 [config.h](../Apply/Logic/Inc/config.h) 加 `extern tagOLED_T tOLEDMain;`。
4. 在 [task_userinit.c](../Apply/Task/Src/task_userinit.c) 加 `OCD_OLED_Init(&tOLEDMain);`。
5. 在 [usercode.c](../Apply/Logic/Src/usercode.c) 业务里直接调 `OCD_OLED_ShowString(...)`。

### 7.3 加一个新片外传感器（OCD 层没有的）
1. 在 [Bsp/OCD/Inc/](../Bsp/OCD/Inc/) 和 [Bsp/OCD/Src/](../Bsp/OCD/Src/) 各加一个文件，命名 `ocd_xxx.h/c`。
2. 函数前缀 `OCD_`，遵循 [SGA 库代码规范 V1.1](SGA库代码规范V1.1.md)。
3. 在 [ocd_conf.h](../Bsp/OCD/Inc/ocd_conf.h) 里 `#include "ocd_xxx.h"`。
4. 后续步骤同 7.2。

### 7.4 改控制策略
- PID 系数：[config.c:321-336](../Apply/Logic/Src/config.c) 的 `PID` / `PID_init`
- 死区/限幅/速率限幅常量：[usercode.c](../Apply/Logic/Src/usercode.c) 顶部 `const float DEAD_ZONE` 等
- 推进器编号映射：[task_thruster.c](../Apply/Task/Src/task_thruster.c) 中的 `&thruster[x]`
- 推力基准：直行 1700 ± offset（[usercode.c `forward_adjust`](../Apply/Logic/Src/usercode.c)），自转 1500 ± offset（`rotate_180_adjust`）

### 7.5 加一个新中断
1. 在 [task_irq.c](../Apply/Task/Src/task_irq.c) 找到对应 `xxx_IRQHandler`。
2. 函数体里加一行 `Drv_xxx_IRQHandler(&handle)`。

### 7.6 切换 RTOS
1. 在 [drv_hal_conf.h](../Driver/Inc/drv_hal_conf.h) 取消 `RTT_ENABLE` 或 `FREERTOS_ENABLE` 宏的注释。
2. 在 [usercode.c](../Apply/Logic/Src/usercode.c) 创建线程，[threadpool.c](../Apply/Logic/Src/threadpool.c) 写线程入口。
3. FreeRTOS 模式还需要手动调一次 `osKernelStart()`。

## 8. 编码与提交规范要点

来自 [SGA库代码规范V1.1.md](SGA库代码规范V1.1.md)，提交代码前必须满足：

| 项 | 规则 |
|---|---|
| 缩进 | 4 空格（用 Tab） |
| 注释 | 必须用 `/* ... */`，不能用 `//`（C 编译器兼容）；有效注释量 ≥ 20 % |
| 变量前缀 | `uc/us/ul/c/s/l/f/d/b/t`（无符号 8/16/32 / 有符号 8/16/32 / float/double/bool/struct） |
| 作用域前缀 | 全局加 `g_`，static 加 `s_` |
| 函数形参 | 必须以 `_` 起头 |
| 函数前缀 | `Drv_*` / `OCD_*` / `Dev_*` / `Algo_*` / `S_*`（本地静态） |
| 结构体类型 | `tagXxxYyy_T` 命名 |
| 大括号 | 独占一行，与引用语句左对齐 |
| 头文件保护 | `__XXX_H_` / `define` / `endif` |
| 文件编码 | GBK |

提交流程（[规范 V1.1 第六节](SGA库代码规范V1.1.md)）：

1. 在自己的板子上充分测试。
2. 把句柄实例填进 [句柄资源示例.txt](句柄资源示例.txt)（如果是修 BUG 可选）。
3. 在 [工程维护记录.txt](工程维护记录.txt) 顶部加一条：日期、作者、说明、改动列表。
4. 拉取最新库，与本地比对。
5. `commit` 信息格式：`<type>(<scope>): <subject>`，type 可选 `feat/fix/docs/style/refactor/perf/test/chore`。
6. 通过 GitHub Pull Request 提交。

## 9. 常见坑

| 现象 | 原因 / 解决 |
|---|---|
| 改了 [config.c](../Apply/Logic/Src/config.c) 引脚不生效 | 没在 [task_userinit.c](../Apply/Task/Src/task_userinit.c) 里调 `Drv_xxx_Init(&handle)`；或 [drv_hal_conf.h](../Driver/Inc/drv_hal_conf.h) 没开 `DRV_HAL_xxx_ENABLE` |
| 串口收不到数据 | [task_irq.c](../Apply/Task/Src/task_irq.c) 的 `USARTx_IRQHandler` 没接 `Drv_Uart_DMA_RxHandler` |
| `Drv_Delay_Ms` 卡死 | 早期版本 BUG，2.3 之后已修；用 `Drv_Delay_Us` 作为基准 |
| 注释全是乱码 | 文件是 GBK，VSCode 默认 UTF-8。右下角切换 `GB2312` 重新打开 |
| FreeRTOS 调度器启动前 `Drv_Delay_Ms` 不工作 | 2.4 已修复；保持库版本 ≥ 2.4 |
| HAL_GetTick 卡死（裸机） | 1.1.8 已修 |
